# 工程规范

## 数据与命名

- Python 代码使用 `snake_case` 文件名和项目既有的驼峰公共字段命名。
- 跨模块数据优先使用 `core.types` 中的不可变数据类。
- 距离、像素和角度的单位写入字段名或文档；内部球面角度使用弧度，比赛文本使用角度。
- 数组边界在模块入口检查，错误通过 `InstaTargetError` 子类传播。

## 生命周期

数据源、后端和结果 sink 都有显式 `open`/`close` 或 `finalize` 生命周期。模型资源由 `buildRuntime()` 创建，由应用入口在 `finally` 中关闭。结果文件采用 `.partial` 写入并在帧序和计数验证后原子发布。

## 可视化与日志

可视化只接收阶段结果，不参与决策。CLI 可以输出进度和错误，库代码通过异常和返回值表达失败；不将调试文本写入标准结果文件。

## 第三方代码

官方 HiT 源树位于 `third_party/HiT`，适配器会在导入官方模块前显式激活该目录。这是模型集成边界的必要行为。第三方源码不应复制到 `src/instatarget`，版本和权重路径通过配置或环境变量指定。

## 配置

配置文件必须满足 `schemaVersion: 1` 的完整字段集合。新增字段应同步更新配置加载器、标准 YAML 和文档；未知字段不得静默接受。
