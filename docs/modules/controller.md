# InstaTargetingSystem 控制器规范

> 本文档定义 DepthAwareTrackController，简称 DTC。  
> 当前第三阶段仅接入 RGB-only 后端输出；深度摘要、深度伪彩色和双 HiT 融合属于后续阶段预留。
> DTC 负责把几何结果、后端输出和多帧运动状态合成可执行的跟踪决策。

---

## 1. 职责边界

| 输入 | 输出 | 不负责 |
|------|------|--------|
| 帧、局部观测、运动状态、可选深度摘要占位 | 搜索计划、模板命令、跟踪结果 | 图像裁剪、模型推理、文件 I/O |

DTC 是控制层唯一有状态模块。它当前持有状态机、运动估计和模板更新规则；深度门控作为后续扩展点保留。
`T0` 线程只通过 DTC 做逐帧决策。

---

## 2. 状态机

```text
INIT -> TRACKING -> UNCERTAIN -> RECOVERING -> TRACKING
                       |             |
                       +-----------> LOST
                                      |
                                      +-> RECOVERING
```

| 状态 | 动作 | 模板更新 |
|------|------|----------|
| `INIT` | 建立首帧模板和初始运动状态 | 只初始化 |
| `TRACKING` | 单视图跟踪 | 允许稳定更新 |
| `UNCERTAIN` | 扩窗验证 | 禁止 |
| `RECOVERING` | 环搜或全景粗搜 | 禁止 |
| `LOST` | 降频搜索并输出预测 | 禁止 |

状态转移只由 `DTC` 决定，不由 `HiT` 或 `geometry` 直接驱动。

---

## 3. 多帧跟踪流程

### 3.1 初始化

1. 读取首帧和初始框。
2. 通过几何层生成首个模板视图。
3. 当前第三阶段不读取深度摘要；若未来启用深度分支，再把初始深度记录并入状态。
4. 生成初始 `MotionState3D`。
5. 提交首帧结果并进入 `TRACKING`。

### 3.2 正常跟踪

1. 读取最近 `n` 帧状态窗口，默认 `n = 3~5`。
2. 当前根据窗口内球面中心和置信度预测下一位置；未来可加入深度摘要。
3. 向几何层请求一个主搜索视图。
4. 将搜索视图送入后端。
5. 使用后端返回的 `fusedScore`、运动连续性和尺度变化做候选选择。
6. 更新状态、模板命令和下一帧搜索计划。

### 3.3 恢复

1. 若置信度下降，进入 `UNCERTAIN`。
2. 若连续低置信，进入 `RECOVERING`。
3. 触发扩窗、环搜或全景粗搜。
4. 当前通过外观和运动门限确认目标；未来可加入深度门限。
5. 找回成功后回到 `TRACKING`，但不立即覆盖首帧模板。

---

## 4. 多帧预测算法

### 4.1 窗口输入

DTC 不是只看一帧，而是使用前 `n` 帧连续观测做路径规划。

窗口内至少包含：

- 最近 `n` 帧球面中心；
- 最近 `n` 帧深度摘要（第四阶段预留）；
- 最近 `n` 帧 BFoV 深度块（第四阶段预留，不作为当前主输入）；
- 最近 `n` 帧置信度；
- 最近 `n` 帧方向变化率。

### 4.2 计算顺序

1. 把球面方向转成单位向量序列。
2. 第四阶段可把深度摘要转成相对距离序列；当前第三阶段跳过此项。
3. 用常速度模型、Alpha-Beta 或 Kalman 在窗口上拟合趋势。
4. 当前用窗口内角速度决定下一帧中心；第四阶段可加入深度跳变约束。
5. 用预测中心生成下一帧搜索视场。
6. 输出 `SearchPlan` 与 `TemplateCommand`。

### 4.3 预测输出

`DTC` 每帧必须产出：

- `predictedMotion`
- `next search center`
- `next search FOV`
- `templateCommand`
- `TrackResult`

---

## 5. 后端输出使用

### 5.1 后端职责

当前第三阶段的深度图处理和 MLP 融合尚未进入运行链路；控制层只消费 RGB-only 后端输出。
第四阶段若启用深度分支，深度图处理、HiT 跟踪和 MLP 融合才会统一放入 `TrackerBackend`。

后端输出至少包含：

- `bbox`
- `modelScore`
- `appearanceScore`
- `depthScore`
- `fusedScore`
- `depthSummary`（当前阶段为 `None`）

### 5.2 控制层使用方式

1. 先按 `fusedScore` 排序候选。
2. 再用 `motionScore` 与 `scaleScore` 做轻量门控。
3. 当前阶段没有深度摘要参与控制；未来启用后，再把它用于状态更新和搜索窗口调整。
4. 当前阶段退化路径就是 RGB + 球面几何。

### 5.3 计算边界

控制层不得再实现深度图编码、RGB 深度双流融合、MLP 融合头或局部视觉特征抽取。

---

## 6. 深度规则

### 6.1 深度摘要

当前第三阶段 DTC 不直接消费深度摘要。若未来启用深度分支，DTC 只消费深度摘要，不直接依赖整张深度图作为主输入。深度摘要至少包括：

- 中位深度
- 平均深度
- 有效比例
- 最小深度
- 最大深度
- 深度置信度

### 6.2 深度用途

以下用途仅第四阶段启用后生效；当前第三阶段不读取深度摘要：

- 估计目标远近变化。
- 调整搜索窗口大小。
- 抑制明显不合理的找回候选。
- 辅助模板更新门控。

### 6.3 深度禁区

- 深度不作为唯一定位依据。
- 深度缺失时 DTC 必须退化为 RGB + 球面几何。
- 深度跳变过大时禁止直接更新稳定模板。

## 7. 与接口的对应

| 文档对象 | DTC 角色 |
|----------|----------|
| `TrackController` | 对外控制器协议 |
| `SearchPlan` | 搜索计划 |
| `InitializationPlan` | 首帧初始化计划 |
| `ProjectedObservation` | 统一后的局部观测 |
| `MotionEstimator` | 运动预测器 |
| `DepthProcessor` | 第四阶段预留深度摘要器（当前第三阶段不启用） |

DTC 的实现必须和 `interface.md` 的方法签名一致，不能自行增加新的状态提交入口。

---

## 8. 模板策略

- 首帧模板只读。
- 稳定模板仅在连续高置信时更新。
- 近期模板用于外观缓变。
- `UNCERTAIN`、`RECOVERING`、`LOST` 禁止更新。

模板污染优先视为控制层错误，不交给 `HiT` 修复。

---

## 9. 失败处理

1. 若 `HiT` 无有效观测，保持预测态。
2. 当前没有深度权重；第四阶段若深度无效，再降低深度分支影响。
3. 若多个候选分数接近，优先保留运动连续性更好的候选。
4. 若连续找回失败，进入 `LOST` 并降频全景搜索。

---

## 10. 接口对齐

本控制器文档对应 `interface.md` 中的：

- `TrackController`
- `SearchPlan`
- `InitializationPlan`
- `ProjectedObservation`
- `MotionEstimator`
- `DepthProcessor`（第四阶段预留）

DTC 是 `process.md` 中 `T0` 的核心职责主体。
