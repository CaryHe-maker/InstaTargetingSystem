# InstaTargetingSystem 总体设计

> **InstaTargetingSystem** 面向 AirSim360 和真实全景视频的实时单目标跟踪。
> 系统以 **360VOT** 处理球面几何，以 **HiT** 完成局部透视跟踪，以
> **DepthAwareTrackController**（简称 **DTC**，深度感知跟踪控制器）融合深度、
> 外观和运动信息完成找回与模板门控。

---

## 1. 目标与约束

| 项目 | 设计目标 |
|------|----------|
| 输入 | AirSim360 全景序列或等价 ERP 视频 + 初始目标框 |
| 输出 | 每帧目标框、置信度、状态；比赛模式只输出官方要求字段 |
| 精度 | 优先提升 OTB `AUC` 与 `Success Rate@0.5` |
| 速度 | 正常帧单视图推理；仅在低置信时增加恢复搜索 |
| 全景能力 | 支持畸变、跨经线、近极点运动和球面尺度变化 |
| 深度能力 | 利用深度估计目标距离变化、搜索半径和恢复优先级 |
| 长时能力 | 遮挡时抑制漂移，丢失后执行局部到全局找回 |
| 部署 | 离线可复现的 Docker 镜像；默认不依赖网络 |

系统不直接把整张高分辨率全景图送入 HiT。HiT 只处理低畸变的局部透视视图；
球面状态是唯一可信位置，ERP 平面框仅用于输入、输出和 OTB 评测。Depth 只作
辅助决策，不替代外观跟踪主线。

---

## 2. 技术选型

| 层级 | 技术 | 职责 |
|------|------|------|
| 数据源 | AirSim360 | 提供 ERP RGB、Depth、semantic mask、instance mask |
| 全景几何 | 360VOT 思路 | BFoV、透视裁剪、局部框回投影、球面评测 |
| 跟踪核心 | HiT-Small | 主线精度/速度平衡 |
| 快速后端 | HiT-Tiny / DyHiT | 端侧或决赛 FPS 优化 |
| 深度控制 | DTC | 深度融合、运动预测、找回规划、模板门控 |
| 训练推理 | Python + PyTorch | 微调、推理和实验 |
| 图像处理 | OpenCV + NumPy | 解码、坐标变换和可视化 |
| 部署 | ONNX Runtime；可选 TensorRT | 固定图尺寸、FP16 推理和端侧加速 |
| 封装 | Docker | 自动评测与环境复现 |

LightTrack 仅保留为速度基线，不进入主线架构。360VOT 是几何与评测基础，
不是跟踪模型。AirSim360 先作为训练、验证和回归数据源，不假设其直接提供官方
比赛格式。

## 3. 系统架构

```text
AirSim360 / ERP 视频 + 首帧框
        |
        v
+------------------+     +----------------------+
| FrameSource      |---->| SphericalGeometry    |
| 解码 / 校验      |     | ERP <-> BFoV / 视图  |
+------------------+     +----------+-----------+
                                  |
                       局部透视搜索图 + 深度摘要
                                  v
                       +----------------------+
                       | HiTBackend           |
                       | 模板 / 搜索 / 置信度 |
                       +----------+-----------+
                                  |
                         局部预测框 + 模型分数
                                  v
+------------------+     +----------------------+
| DepthAware       |<--->| TrackController     |
| MotionEstimator   |     | 状态机 / 门控 / 恢复 |
+------------------+     +----------+-----------+
                                  |
                         BFoV + ERP BBox
                                  v
                       +----------------------+
                       | ResultSink / Eval    |
                       | 输出 / OTB / 360VOT  |
                       +----------------------+
```

模块依赖固定为：

```text
core <- geometry <- tracker <- controller <- app
  ^         ^          ^           ^          |
  +---------+----------+-----------+----------+
                    config / diagnostics
```

`geometry` 不依赖 HiT；`tracker` 不解释球面坐标；`controller` 不直接调用
PyTorch。模块只通过 `interface.md` 中的数据契约通信。

## 4. 核心表示与算法

### 4.1 球面坐标

ERP 图像尺寸为 `W x H`，像素中心 `(u, v)` 映射为：

```text
yaw   = 2π * ((u + 0.5) / W - 0.5)       ∈ [-π, π)
pitch = π  * (0.5 - (v + 0.5) / H)       ∈ [-π/2, π/2]
```

内部位置使用单位向量、深度和 BFoV：

```text
SphericalPoint = unit_xyz + yaw + pitch
DepthState     = range + rangeVelocity + confidence
BFoV           = center + horizontal_fov + vertical_fov + roll
```

`yaw` 只用于显示和序列化。运动预测在单位球面切平面上进行，避免 `+π/-π`
跳变；接近极点时仍以单位向量更新，不以 yaw 差分更新。深度只用于辅助
预测和恢复，不作为单独定位真值。

### 4.2 BFoV 透视裁剪

1. 以预测球面中心建立局部相机坐标系。
2. 根据目标尺度、深度和速度确定水平/垂直 FOV。
3. 将局部透视像素反投影为单位射线。
4. 旋转射线至全景坐标系，再采样 ERP 图像。
5. 水平方向循环采样，垂直方向钳制到图像边界。

局部框回投影时采样框边界而非只映射四个角，以降低大 FOV 和高纬度下的
曲边误差。结果先生成 BFoV，再由输出适配器生成 ERP `BBoxXYWH`。

### 4.3 HiT 局部跟踪

首帧流程：

1. 将初始 ERP 框转换为 BFoV。
2. 生成低畸变模板图和模板框。
3. 初始化 HiT 模板特征、球面运动状态和深度参考值。

逐帧流程：

1. 根据上一状态预测球面中心、目标尺度和目标深度。
2. 生成一个正常搜索视图。
3. HiT 输出局部框和原始置信度。
4. 回投影至球面，计算融合置信度。
5. 状态机接受、扩搜或拒绝该观测。

融合置信度由 HiT 分数、外观相似度、球面运动一致性、尺度一致性和深度一致性
组成。各项权重写入配置，不写死在代码中。

### 4.4 状态机与找回

```text
INIT -> TRACKING -> UNCERTAIN -> RECOVERING -> TRACKING
                       |             |
                       +-----------> LOST
                                      |
                                      +-> RECOVERING
```

| 状态 | 行为 | 模板更新 |
|------|------|----------|
| `TRACKING` | 单 BFoV 正常搜索 | 连续高置信且外观稳定时允许 |
| `UNCERTAIN` | 扩大 FOV，多尺度验证 | 禁止 |
| `RECOVERING` | 邻域环搜，超时后全景分块搜索 | 禁止 |
| `LOST` | 降频全景搜索，输出预测框并标记失效 | 禁止 |

找回分三级：

1. **扩窗搜索**：围绕预测中心扩大 FOV。
2. **球面环搜**：沿预测中心周围布置候选视图，批量送入 HiT。
3. **全景粗搜**：用固定重叠的 BFoV 网格覆盖球面，取 Top-K 后精搜。

候选必须同时通过外观阈值、运动门限和深度门限。深度门限用于抑制明显错误的
远近跳变。找回成功后重置运动协方差，但不立即覆盖首帧模板。

### 4.5 模板策略

模板库最多保存三类模板：首帧模板、稳定模板、近期模板。

- 首帧模板只读，始终保留。
- 稳定模板仅在连续高置信帧更新。
- 近期模板用于外观缓变，不参与单独找回确认。
- `UNCERTAIN`、`RECOVERING`、`LOST` 状态禁止更新。

该策略防止遮挡物、相似目标或错误深度导致模板污染。

## 5. 数据与训练

### 5.1 数据源

1. AirSim360 仿真全景数据，含 RGB、Depth、semantic mask、instance mask。
2. 真实场景全景跟踪数据。
3. 360VOT 数据用于全景预训练、属性评测和回归测试。
4. 常规 SOT 数据只用于 HiT 基础能力，不替代全景微调。

### 5.2 训练样本

- 从 AirSim360 instance mask 和 ERP 标注生成模板/搜索 BFoV 对。
- 增加跨经线、高纬度、尺度突变、模糊、遮挡和深度突变采样权重。
- 随机改变 BFoV 中心与 FOV，模拟运动预测误差。
- 对真实与仿真数据分层采样，避免仿真外观占主导。

### 5.3 训练阶段

| 阶段 | 内容 | 产物 |
|------|------|------|
| A | 使用官方权重跑通普通视频 | 可复现 HiT 基线 |
| B | 接入 BFoV，不改权重 | 全景几何基线 |
| C | 接入 AirSim360 深度摘要 | 深度门控基线 |
| D | 全景样本微调 HiT | 主线权重 |
| E | 加入困难样本和模板门控 | 长时版本 |
| F | 蒸馏、FP16、ONNX/TensorRT | 部署权重与引擎 |

训练、验证、测试序列按视频划分，禁止同一视频的相邻帧跨集合。

## 6. 评测与性能

### 6.1 官方主指标

按比赛 OTB 协议计算：

- `Success Rate@0.5`：`IoU > 0.5` 的有效帧比例。
- `AUC`：阈值 `0.00..1.00`、步长 `0.05` 的成功率均值。
- `FPS`：端到端有效帧数除以总墙钟时间，包含几何与后处理。

### 6.2 内部诊断指标

- 360VOT 球面角度精度和 dual success rate。
- `CB`（跨边界）、`LD`（大畸变）、`SA`（拼接伪影）属性结果。
- 找回成功率、平均找回帧数、误找回率。
- `TRACKING/RECOVERING/LOST` 状态占比。
- 深度一致性命中率、深度跳变误报率。

### 6.3 性能预算

先测量后设硬阈值。每次实验至少记录：解码、投影、HiT、深度统计、回投影、状态
更新和总耗时的 `P50/P95`。优化顺序固定为：减少搜索次数、批量恢复候选、FP16、
ONNX，最后才使用 TensorRT 自定义部署。

## 8. 实施计划

### 8.1 M1：可运行基线

- 封装 `HiTBackend.initialize()` / `infer()`。
- 完成视频输入、首帧框和逐帧输出。
- 在普通视频上验证与官方 HiT 结果一致。

**门禁**：完整序列可运行；输出帧数与输入帧数一致。

### 8.2 M2：360VOT 几何层

- 实现 ERP/BFoV 转换、透视裁剪与局部框回投影。
- 覆盖赤道、跨经线和近极点单元测试。
- 接通 HiT-Small 全景跟踪链路。

**门禁**：几何往返误差达标；跨经线时内部轨迹连续。

### 8.3 M3：深度增强控制器

- 实现深度摘要、目标距离估计和速度粗估。
- 将深度一致性纳入置信融合与恢复决策。
- 基于 AirSim360 生成深度驱动的回归集。

**门禁**：深度异常帧不会误触发稳定模板更新。

### 8.4 M4：长时跟踪

- 实现融合置信度、状态机和模板保护。
- 实现扩窗、环搜和全景粗搜。
- 建立遮挡、相似目标和再出现回归集。

**门禁**：找回提高 AUC，且误找回率不劣于基线。

### 8.5 M5：全景微调

- 构建 BFoV 训练对与困难样本采样。
- 微调 HiT-Small，对比 HiT-Tiny 和 DyHiT。
- 固定主模型、阈值与消融实验表。

**门禁**：验证集 AUC、`Success Rate@0.5` 均高于 M2。

### 8.6 M6：部署与提交

- 导出 ONNX，验证 PyTorch/ONNX 输出误差。
- 优化 FP16、候选批处理和内存复用。
- 构建无网络 Docker，接入官方输入输出适配器。

**门禁**：镜像冷启动成功；固定样例结果可复现；FPS 与精度报告完整。

## 9. 风险与降级

| 风险 | 处理 | 降级方案 |
|------|------|----------|
| 官方接口未公布或变化 | 所有外部格式集中在 `CompetitionAdapter` | 保留文件式 `xywh` 适配器 |
| 高纬度回投影误差 | 增加边界采样，内部以 BFoV 为准 | 限制单视图 FOV，拆成多视图 |
| 深度噪声或缺失 | 只把深度用于门控，不作为唯一证据 | 退化为 RGB + 球面几何 |
| 找回拖慢平均 FPS | 仅低置信触发，候选批推理 | 降低全局搜索频率 |
| ONNX 算子不兼容 | 提前建立导出测试 | 使用 PyTorch 后端提交 |
| TensorRT 数值偏差 | 后端一致性回归 | 回退 ONNX Runtime FP16/FP32 |
| 模板污染 | 状态门控与首帧模板只读 | 完全关闭在线更新 |
