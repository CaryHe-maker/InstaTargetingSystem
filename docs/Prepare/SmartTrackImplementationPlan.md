# SMART-TRACK 实施方案

## 1. 结论

SMART-TRACK **不是传统视觉跟踪器本体**，而是一个
**Kalman Filter 驱动的传感器融合跟踪框架**。

它的价值在于：

1. 它把“预测”和“测量”分开。
2. 它把深度当成 3D 位置测量，而不是普通附加特征。
3. 它强调检测失败时，用预测结果反向指导搜索区域。

结论：**SMART-TRACK 最适合做本项目 DTC 的运动预测与恢复思路参考。**

## 2. 参考依据

官方资料：

- GitHub: https://github.com/mzahana/SMART-TRACK

仓库说明里最重要的点是：

- 使用 YOLOv8 做检测。
- 使用深度图计算目标 3D 位置。
- 使用 Kalman Filter 做状态预测。
- 检测失败时，用预测位置反向生成 ROI。

这和本项目的 DTC 逻辑非常接近。

## 3. 适配思路

SMART-TRACK 的核心不是“模型更强”，而是“控制逻辑更清楚”。

对本项目最有用的部分是：

1. 深度 -> 3D 位置。
2. 3D 位置 -> Kalman 状态。
3. 状态预测 -> 下一次搜索 ROI。
4. 检测失败 -> 用预测继续找。

这正好对应本项目的：

- `DepthProcessor`
- `MotionEstimator`
- `DTC.plan()`
- `DTC.update()`

## 4. 技术栈

### 4.1 语言

- Python：主逻辑。
- ROS2：原项目依赖，但本项目不必完整引入。
- OpenCV：图像处理。

### 4.2 核心组件

- 检测器
- 深度转 3D 的测量模块
- Kalman Filter
- ROI 规划模块

## 5. 实施步骤

### 阶段 1：抽象出控制逻辑

目标：把 SMART-TRACK 从机器人系统中抽出来。

工作项：

1. 只保留“检测 -> 测量 -> 预测 -> ROI”的主链路。
2. 去掉 ROS2 绑定。
3. 去掉对特定无人机平台的依赖。

验收：

- 能用纯 Python 解释其核心流程。

### 阶段 2：映射到本项目

目标：把它映射到 DTC。

工作项：

1. 用球面方向代替普通图像平面坐标。
2. 用 BFoV 深度块代替普通相机的深度测量。
3. 用 Kalman / Alpha-Beta 代替重型学习预测。
4. 用预测中心生成下一帧 BFoV。

验收：

- 运动预测能直接写进 `controller.md`。

### 阶段 3：控制层落地

目标：把预测和恢复写成可执行代码。

工作项：

1. 目标丢失时保留预测状态。
2. 用预测位置生成搜索窗口。
3. 检测失败时继续用预测值扩展搜索。
4. 深度缺失时只保留球面方向预测。

验收：

- 恢复阶段有明确的搜索中心和搜索半径。

## 6. 风险点

1. SMART-TRACK 原始实现偏 ROS2 和检测器融合，不是全景跟踪。
2. 它依赖测量连续性，检测完全失效时仍要补搜索策略。
3. 需要把平面坐标换成球面坐标。

## 7. 最终建议

SMART-TRACK 最适合当作：

1. DTC 的状态预测参考。
2. 恢复搜索参考。
3. 深度测量 -> 3D 状态的参考。

它不适合直接作为本项目主 tracker。
