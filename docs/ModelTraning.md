# ModelTraning

> 本文定义最后一个阶段的模型训练规约。它只描述收尾训练、校准和导出方式，不改变推理契约、控制层或数据接口。

## 1. 目标
- 只训练模型相关模块
- 保持 `core`、`geometry`、`controller`、`io` 的接口不变
- RGB-only 目标是稳定 `appearanceScore` 和局部框
- RGB-D 目标是在 RGB 基础上校准 `depthScore` 与 `fusedScore`

## 2. 输入
- 已对齐的数据序列
- 固定版本的配置文件
- 已登记的超参数和权重路径
- 固定随机种子

## 3. 训练顺序
1. 固定数据划分，先锁定训练集、验证集和测试集
2. 先跑一轮只读检查，确认样本、标注、序列号和帧号连续
3. 载入基线权重，恢复可复现的初始状态
4. 先微调 RGB 主干，再启用深度分支和融合头
5. 最后只做小学习率收敛和阈值校准，不新增结构

## 4. 冻结规则
- 几何层默认冻结
- 控制层默认冻结
- 输入输出协议冻结
- 主干骨干和融合头按阶段逐步解冻
- 只在评审批准后修改超参数或结构

## 5. 损失与指标
- 框回归损失
- 分类或匹配损失
- 深度分支损失
- 融合一致性损失
- 验证指标至少记录 `AUC`、`Success Rate@0.5` 和 `FPS`

## 6. 训练过程
1. 以序列为单位构建 batch，避免打散同一序列的时间顺序
2. 每次只更改一个训练因素
3. 记录训练日志、配置快照、权重哈希和数据版本
4. 每个阶段结束后跑一次验证集
5. 通过后再进入下一阶段

## 7. 输出
- `checkpoint_best.*`
- `checkpoint_last.*`
- `metrics.json`
- `train_log.jsonl`
- `config_snapshot.yaml`

## 8. 验收
- 验证集指标不低于基线
- RGB-only 退化路径仍然成立
- 深度关闭时输出必须满足 `depthScore = 0` 且 `fusedScore = appearanceScore`
- 重新加载权重后结果可复现
- 导出权重可直接接入现有推理链路

## 9. 禁止事项
- 不在训练阶段修改推理契约
- 不混用训练集和验证集
- 不在同一次实验里同时改结构和阈值
- 不记录不完整的配置和权重来源
- 不跳过序列级别验证

## 10. 交付模板
```text
run_id:
base_config:
train_data:
val_data:
seed:
frozen_modules:
trainable_modules:
best_checkpoint:
metrics:
notes:
```

## 11. 最终要求
- 训练完成后只保留一个主结果和一个备用结果
- 所有产物必须可追溯到配置、数据和代码版本
- 若后续要改训练流程，先更新本文，再改代码
